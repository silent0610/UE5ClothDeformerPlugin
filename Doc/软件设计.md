# 软件设计

软件开发生命周期（SDLC）通常将软件的设计与施工流程划分为几个标准阶段。以下是通用的流程概览，以及对“需求分析”阶段的详细拆解。

## 1 软件开发全流程阶段

通常分为以下 **6 个主要阶段**：

1. **需求分析 (Requirements Analysis):** 明确“要做什么”。这是基石，决定软件的功能和目标。
2. **系统设计 (System Design):** 明确“怎么做”。
    - **概要设计 (High-Level Design):** 架构、技术选型、模块划分。
    - **详细设计 (Low-Level Design):** 具体接口、数据结构、算法逻辑。
3. **编码/施工 (Implementation/Coding):** 将设计转化为代码。
4. **测试 (Testing):** 验证软件是否符合需求，发现并修复 Bug（单元测试、集成测试、系统测试）。
5. **部署 (Deployment):** 将软件发布到生产环境供用户使用。
6. **维护 (Maintenance):** 修复上线后的问题、优化性能或增加新功能。

## 2 需求分析阶段详解

这个阶段的核心目的是**把模糊的想法转化为清晰、可执行的文档**。

### 2.1 **A. 应该做哪些事情 (核心活动)**

1. **需求获取 (Elicitation):**
    - **访谈与调研:** 与客户、潜在用户或业务专家沟通，挖掘痛点和期望。
    - **竞品分析:** 研究市场上同类软件的功能和优缺点。
    - **场景模拟:** 定义用户在特定场景下如何使用软件（User Stories）。
2. **可行性分析 (Feasibility Study):**
    **技术可行性:** 现有技术能否实现？是否有难点？
    - **经济可行性:** 预算是否足够？投入产出比（ROI）如何？
    - **时间可行性:** 能否在规定期限内完成？
3. **需求分类与定义:**
    - **功能性需求:** 系统必须具备的具体功能（如“用户可以登录”、“系统支持导出PDF”）。
    - **非功能性需求:** 对性能、安全性、可靠性、扩展性的要求（如“响应时间小于1秒”、“支持1万并发”）。
4. **需求确认与评审:**
    - 与利益相关者（Stakeholders）反复确认理解是否一致，避免“做出来的不是用户想要的”。

### 2.2 **B. 得到哪些成果 (核心交付物)**

这是进入下一阶段（设计）的凭证，通常包括：

| **交付成果**                        | **描述**                                  |
| ------------------------------- | --------------------------------------- |
| **软件需求规格说明书 (SRS)**             | **最核心文档**。详尽描述所有功能和非功能需求，是后续开发和测试的标准依据。 |
| **用例图/用例描述 (Use Cases)**        | 描述用户（Actor）与系统交互的具体流程。                  |
| **原型图 (Prototypes/Wireframes)** | 低保真的界面草图，用于直观展示交互逻辑和布局（非最终UI设计）。        |
| **流程图 (Flowcharts)**            | 梳理核心业务的流转逻辑（如订单处理流程）。                   |
| **数据字典 (Data Dictionary)**      | 初步定义系统中涉及的关键数据及其属性。                     |

## 3 系统设计阶段

### 3.1 概要设计 (High-Level Design, HLD)

**核心目标：** 宏观架构，确立系统的整体骨架。解决“系统由哪些部分组成”的问题。

#### 3.1.1 应该做哪些事情 (核心活动)

1. **架构模式选择:** 决定采用何种架构（如：微服务、单体架构、分层架构、客户端-服务器模式等）。
2. **技术选型:** 确定编程语言（如 C++）、数据库（MySQL/Redis）、通信协议（HTTP/TCP）、第三方库或框架。
3. **模块划分 (Subsystems):** 将系统拆分为若干个子系统或大模块，并定义模块之间的边界。
4. **数据模型设计 (概念/逻辑):** 设计核心业务实体及其关系（ER 图），确定数据流向。
5. **接口设计 (宏观):** 定义模块与模块之间、系统与外部系统之间的交互方式和通讯协议。

#### 3.1.2 成果

- **系统架构图**展示系统组件、服务器部署、网络拓扑的顶层视图
- 模块结构图
- 技术选型文档
- 数据库概要设计
- 实体关系图
- 接口规范

### 3.2 详细设计

#### **A. 应该做哪些事情 (核心活动)**

1. **类与对象设计:** 根据你的 C++ 规范，设计具体的类（`MyClass`）、结构体（`MyStruct`）、成员变量及函数的签名。
2. **算法与逻辑设计:** 针对复杂的业务逻辑或计算，设计具体的算法流程或伪代码。
3. **数据库物理设计:** 将 ER 图转化为具体的数据库表结构、索引、视图、存储过程。
4. **文件结构规划:** 规划具体的物理文件组织（如确定哪些类放在 `MyClass.ixx`，哪些实现放在 `MyClass.cpp`）。
5. **错误处理设计:** 定义具体的错误码、异常捕获机制和日志记录格式。

#### 成果

- **类图 (UML Class Diagram)**详细展示类名、属性、方法以及类之间的继承/组合关系。
- **时序图 (Sequence Diagram)**展示对象之间在特定场景下的交互顺序和消息传递。
- **API 详细定义**具体的函数签名（输入参数、返回值）、HTTP 接口文档（Swagger/OpenAPI）。
- **数据库物理模型**建表脚本（SQL），包含字段类型、长度、主外键约束。
- **伪代码/流程逻辑**针对核心复杂函数的具体实现步骤描述。
