# 服装形变插件需求规格说明书

V1.0.0
2026-02-02

## 1 介绍

### 1.1 目的

设计并开发一款 Unreal Engine 5 插件, 集成 OnnxRuntime, 基于 [[SNUG.md|SNUG]] 算法。该插件旨在连接 UE5 动画系统与渲染管线，通过 ONNX Runtime 推理深度学习模型，实现低模驱动高模的实时高质量服装形变。

### 1.2 范围

- **输入**：ONNX 模型文件 (不同服装不同模型)、低模 (Proxy Mesh)、高模 (Render Mesh)、实时骨骼动画数据。
- **输出**：实时变形的高模网格。
- **核心流程**：模型导入 -> 映射关系构建 (Bake) -> 运行时推理 -> **CPU 顶点形变**[^1]。

## 2 总体描述

### 2.1 用户角色

- 负责在编辑器中导入模型、配置高低模映射关系、调试形变效果。

### 2.2 运行环境

Win11, UE5.6, 
依赖库: ONNX Runtime

## 3 功能需求

### 3.1 资产管理

- **FR-01 模型导入与封装**
    - 系统需定义新的资源类型 `ModelAsset`。
    - 提供导入机制, 读取外部 `.onnx` 文件
    - 必须将模型二进制数据**序列化**为资产内部的 `TArray<uint8>` 字节流，以摆脱对原始 `.onnx` 文件的路径依赖，确保项目打包（Packaging）后的可用性。[^2]
- **FR-02 映射数据资产**
    - 系统需定义资源类型 `MappingAsset`，用于存储低模与高模的索引对应关系及权重。

### 3.2 编辑器面板

- **独立窗口**, 还不知道咋搞
- 输入槽：允许用户拖入 Source Mesh (Low Poly) 和 Target Mesh (High Poly)。
- 参数配置：提供 KNN 参数 $K$ 值设置（默认 K=3）。
- 执行：点击“Build Mapping”按钮后，基于 KNN 算法计算每个高模顶点对应的 K 个低模顶点索引及权重。生成并保存 `MappingAsset` 资产。
- 未来可能需要支持选择不同的**映射策略**

### 3.3 运行时

- **FR-04 组件化集成**
    - 提供一个组件,
    - 组件需暴露属性槽位，用于指定 `ModelAsset` 和 ` MappingAsset `。且只需这两个, 不需要额外给定低模[^3]
- **FR-05 Input Adapter**
    - 实现 Adapter 以适应不同模型看所需输入, 默认实现 `SnugAdapter`
    - 插件需 Hook 宿主 Actor 的动画更新事件。
    - 自动获取 $\beta$ (体型参数)。
    - 自动获取 $\theta$ (骨骼位姿) 和 $v$ (根节点速度)。
    - 注意处理坐标系
- **FR-06 推理**
    - 在 `Tick` 中执行。`TickComponent`
    - 插件需要管理 ONNX Session 生命周期。
    - 维护时序状态：内存中需缓存上一帧的 Hidden State ($h_{t-1}$) 作为当前帧输入，推理结束后更新为 $h_t$。
- **FR-07 状态重置**
    - 提供 BlueprintCallable 接口 `ResetState()`。
    - 调用时将 Hidden State 清零，防止瞬移导致的速度突变引发模型“爆炸”。
- **FR-08 CPU 顶点形变 (V1 实现)**
    - 推理输出：获取低模 T-Pose 偏移量。
    - 映射计算：在 CPU 端根据 KNN 权重计算高模偏移。
    - 网格更新：直接修改 `USkeletalMesh` 的动态顶点缓冲或通过 `ProceduralMesh/DynamicMesh` 提交更新。
    - _注意：此环节为可能为 V1 性能瓶颈，仅适用于中低面数高模。_

## 4 非功能需求

- 性能要求
    - 推理
    - 更新
- DLL 兼容 或 自包含, 不依赖 内置 onnx

[^1]: 暂时, 后续出于性能考虑可能转为GPU
[^2]: 实现失败, 被内置插件截胡了, 目前需要手动创建资源, 指定类型, 并给出模型路径
[^3]: 场景中物体是高模, 插件获取位姿和动作, 输入模型得到低模偏移, 根据映射直接得到高模偏移, 不需要低模作为输入.
